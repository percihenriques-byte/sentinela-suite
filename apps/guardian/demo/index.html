O filtro de hoje desliga sozinho.
O nosso, não.

O SafeSearch comum vive no navegador. Por isso, basta abrir uma aba anônima para ele sumir. O Sentinela move a proteção para a camada de rede, onde o modo incógnito não alcança. Teste você mesmo abaixo.

Por que funciona

A proteção sai do navegador e vai para a rede

O segredo é onde o filtro mora. O navegador é fácil de driblar. A camada de rede acontece antes do navegador, então o modo incógnito não tem o que desligar.

📱

Dispositivo

O aparelho da criança faz uma busca, em qualquer navegador ou aba anônima.

Sentinela (DNS)

Antes de chegar ao buscador, o pedido passa pelo DNS do Sentinela, que força o modo seguro.

→
🔎

Buscador

O Google/Bing/YouTube só responde na versão segura. Conteúdo impróprio nem aparece.

# o navegador pede www.google.com, mas o DNS do Sentinela responde:
www.google.com  →  forcesafesearch.google.com
www.youtube.com  →  restrict.youtube.com  // vale até no modo incógnito

🖥️ Isto não é só uma maquete

O Sentinela tem um app real para Windows que aplica exatamente essa proteção no computador da família — sem instalar Python, sem servidor, sem mensalidade. A instalação é um clique e pede a senha de administrador uma única vez.

PS> .\Instalar-Sentinela.ps1
Sentinela · protótipo conceitual para o Desafio Liga Jovem
Esta é uma simulação para fins de demonstração. Nenhuma busca real é feita e nenhum conteúdo impróprio é exibido — as "buscas bloqueadas" servem apenas para mostrar o comportamento do filtro. A técnica de DNS seguro citada (forcesafesearch / restrict.youtube) é real e usada por escolas e provedores.
